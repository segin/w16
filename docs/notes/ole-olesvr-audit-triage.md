# OLESVR.DLL audit triage

An outside, read-only audit of w16's OLE 1.0 libraries (not in the
repository) listed findings for OLESVR.DLL (`ole/olesvr/`: svr.c, doc.c,
util.c, entry.asm, olesvr.lnk) as C5-C6, H8-H11, M11-M17 and L9-L12 (its
numbering, shared with OLECLI's findings, triaged on their own). Each one
was checked by reading the current code and what ARCHITECTURE.md 16 and
the code's comments record of 3.1's OLESVR (tests/olesvr probes). No
emulator was run for the triage itself.

Verdicts: **REAL** (confirmed; fixed), **FALSE** (the claim is wrong),
**PARTLY** (some sub-claims hold: those are fixed), **3.1-BEHAVIOUR**
(3.1 does the same: kept), **HARDENING** (only with malformed input, a
misbehaving server or client, or an exhausted heap; fixed when cheap and
invisible to working use), **UNSURE** (needs a run of 3.1; the code is
left alone and the probe is described). Where 3.1 itself dies, w16 may
live.

Status: every finding has a verdict; M13 waits for a 3.1 probe
(2026-11-26). L9 was first fixed and then reverted when the boot test
showed 3.1 doing the same.
