## Goal and plan (the user's, 2026-11-13)

386 Enhanced mode boots to Program Manager and is usable (mouse, keyboard, display, exit) with w16's WIN386.EXE: first with Microsoft's KRNL386/USER/GDI/drivers, then with as many w16 parts as run there.
1. Fix the INT 74h reflection with PM selectors in DS/ES, and the bad-CS resume after INT 2Fh 4003h. **Done.**
2. w16's own VxD services that the System VM's drivers call (VMD, VDD, Reboot, VKD, VPICD, VTD...), observed black-box (probes) and from the DDK docs. **The boot's calls done** (VX5); Ctrl+Alt+Del, DOS boxes etc. later.

## Fixed (2026-11-13)

- IRQ 8-15 vectors (70h-77h) chained from a PM handler to the host's default were reflected as software interrupts: DS/ES translation messages for every mouse interrupt, and the V86 handler's registers copied into the interrupted code (the "bad CS" panic).
- MOUSE.DRV's INT 15h C207h (PS/2 handler) from PM: the BIOS gets a V86 breakpoint (W386_BP_PS2CB) that runs the PM handler on the host stack with status, X, Y, 0.
- Exit Windows: KRNL386 ends with INT 21h AX=0001h; treated as 4C00h, after making the client's PSP current (as w16's DOSX).
- (2026-11-19, a user report) Exit Windows with w16's KRNL386 under w16's WIN386 ended in a GP fault in USER (0497:8204, err 0D40). terminate_client() takes a 4Ch with a task's PDB current for that task's end (task_exit: ends the PDB, returns), and w16's KERNEL made its final 4Ch with Program Manager's PDB still current, so it came back from it. Fixed in KERNEL (kexit_to_dos makes its own PSP current first, as Microsoft's KRNL386 does; ExitKernel pops its word); WIN386 unchanged. Microsoft's WIN386 ended w16's KRNL386 cleanly even before the fix. Boot-test case `exittree` (w16's WIN386, Microsoft's, Standard mode).
- Nested interrupts on the host stack overwrote the running handler's pushed data (the intermittent #GP/hang): hstk_base/hstk_run/dpmi_note_pm in dpmi.c.
- Nested interrupts on the V86 reflection stack overwrote the interrupted V86 code's stack (hang while fonts loaded, ~1 in 7 under load): traps from V86 code on that stack lower its start (vmm.c trap()); stack 8 KB with an overflow check. 40/40 boots after.
- VMM heartbeat in the trace every 20 s of ticks: V86/PM position, stack, registers (code bytes removed 2026-11-14: clean room, ARCHITECTURE.md 3; also from the client-exception panic and the V86 #GP panic), IRQ counts, PIC masks. Use it on any hang.

## VDD services the 386 grabber needs (from the grabber agent)

WINOA386.MOD's grabber (Microsoft's VGA.3GR and w16's,
`drivers/grabber/vga3gr/`) reaches the VDD (device 000Ah) through its
protected-mode API entry: INT 2Fh AX=1684h BX=000Ah from the System VM must
give ES:DI = a callable entry. Calls (observed on 3.1 with GR3; details in
docs/notes/grabber-handover.md "VGA.3GR"): EAX = function (only AX
matters: Microsoft's grabber leaves garbage in the high word), EBX = the
DOS box's VM handle, ES:EDI = a buffer in the caller's segment (16-bit
offset), ECX its size; results in the registers and the buffer.

- 0 Get_Version: EAX = 030Ah, 8 bytes "VIDEOVGA" to ES:EDI (both grabbers
  refuse other strings / major versions).
- 1 Get_Mem (28h bytes): dwords: linear addresses of planes 0-3 of the
  VM's video memory (text modes: plane 0's address must show the text as at
  B800:0000, char/attribute pairs, 160 bytes a row), a start offset (0),
  the four sizes, one more address. The VM must not run until Free_Mem.
- 2 Get_State (1Ch): mode, 0, flags (bit 1 = cursor tracking), rows (19h),
  cursor column, row (words), cursor start, end (words), 16 palette
  registers.
- 3 Get_Mod (100h): flags word (8 controller, 10h memory, 20h cursor),
  count, then text modes: changed cells in AL=left AH=top BL=right
  BH=bottom (inclusive; FFFFh in AX and BX = all); graphics: count = 4 KB
  pages of a plane, a bit per page from +4. Holds the VM (GetDisplayUpd)
  until Free_Mem / Unlock_App.
- 4 Clear_Mod, 5 Free_Mem, 9 Unlock_App: no buffer.
- 6 Get_GrbMem (as 1), 8 Get_GrbState (as 2), 7 Free_Grab: the copy taken
  at Alt+PrintScreen in a full-screen VM.
WINOLDAP also passes RNG1DSSEL (7Bh, a flat selector) and the VM handle in
the EXTPAINTSTRUC; w16's grabber maps the linear addresses with its own
selectors (SetSelectorBase), so they must be valid in the System VM.
